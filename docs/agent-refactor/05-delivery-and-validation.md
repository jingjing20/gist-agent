## 快速验证

按变更选择最小相关检查，不需要每次全部执行：

| 命令 | 主要覆盖 |
| --- | --- |
| pnpm typecheck / pnpm build | 类型及构建 |
| pnpm test:analysis-core | 模型循环、工具协议、提交和预算 |
| pnpm test:memories | 记忆及候选规则 |
| pnpm test:analysis-state | 多轮状态、草稿、上下文和证据复用 |
| pnpm test:analysis-presentation | 证据接口、分页和展示资产结构 |
| pnpm test:analysis-cutover | 唯一入口及退役约束 |
| pnpm test:analysis-failures | SQL / 提交失败反馈及恢复 |
| pnpm test:reasoning | 供应商推理参数相关回归 |
| pnpm test:security-quality / pnpm test:schema-ranking | SQL 安全、结果质量及 Schema 目录排序的离线检查 |

纯文档整理只检查链接、脚本名称及差异，不追加业务测试。`test:*:integration`、`smoke:conversation` 和 `benchmark:*` 依赖真实数据库或服务，执行前先读脚本。

真实外部模型、数据库集成、浏览器 E2E、完整回归和人工交互仅按用户安排执行。

输入以 [agent-core-cases.json](../../benchmarks/saas-growth/agent-core-cases.json) 为准；数值基准来自 [cases.json](../../benchmarks/saas-growth/cases.json)，不复制第二套预期数字。操作与审核步骤见[验收 walkthrough](../../benchmarks/saas-growth/acceptance-walkthrough.md)。

| 案例 | 验收重点 |

| C07 | SQL 错误回主循环，修正可见且计入预算 |
| C08 | 预算 partial、明确取消及停止副作用 |
| C09 | 匹配证据重画图；最新数据要求触发重查 |
| C10 | 数据源权限、外部文本注入及证据授权 |

## 外围验收 P01～P07

| ID | 操作 | 预期 |
| --- | --- | --- |
| P01 | A 生成中切到 B | A 继续，迟到事件不串入 B，不发送取消 |
| P02 | A 未完成时切回 | 补齐遗漏并继续接收，无重复、乱序或重问 |
| P03 | A 完成后切回 | 恢复完整结果和终态，不残留 loading |
| P04 | A、B 并发并反复切换 | 各自状态、证据和事件隔离，遵守并发限制 |
| P05 | SSE 断连或重复事件 | 快照和实时事件有序去重，不重复执行 SQL |
| P06 | 取消 A 后切换 / 重连 | A 保持取消，停止后续副作用，B 不受影响 |
| P07 | 数据源、上传、表管理及认证 | 原入口和权限保持，记忆页不替代数据源页 |

## 结果记录与完成条件

每次验收记录 Git commit、模型与参数、数据版本、定义 id/version、权限、消息序列、证据、实际结果及审核人；状态使用 pass / fail / needs-review，未执行保持 not_run。C 案例结果写入验收 JSON，P 场景记录操作和观察证据。

对照使用同一模型、数据、定义和权限，每次只改变一个策略。无法建立等价基线时注明限制，不计算虚构收益。数值、口径、证据充分性、验证针对性、未决问题、预算和工具次数分开评价。

完成条件是核心业务和外围行为有实际验收记录，限制被明确说明，旧核心没有成为第二条运行路径。mock、构建或界面存在本身不能证明业务目标完成。
