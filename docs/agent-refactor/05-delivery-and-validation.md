### S0：建立实施基线

- 检查工作区和现有测试依赖，记录需要保留的行为，不复制整套旧模块。
- 按 D19/D20 盘点实际技术栈及多会话订阅、后台任务、事件恢复链路；记录相关代码与已有验证证据，固定不得退化的基线，不在本轮更换技术选型。
- 定义新核心 model/tool/storage 接口；mock 驱动同一真实循环，不用另写一套测试循环。
- 从标准答案选择有效时间区间；新增对比题时，先审查参考 SQL，不能用被测 Agent 的输出当标准。
- 记录现有数据源权限、generation finalize 与迁移 API 的实际签名，补齐 adapter 实现计划。
- 新增表/字段采用现有迁移机制；先新增后接入，保持旧运行链路暂时可用。

### S1：先跑通业务链路

- 使用经确认的 SaaS 种子定义及完整小 Schema，内容使用最终定义结构，repository 可暂为 fixture 适配器，不形成生产双源。
- 暂使用最小 run state，保留最终 stateRevision/definitionRefs 契约，S3 再加入跨轮 patch。
- 接入现有 Worker 外壳和 UI 基础消息，不能以 CLI 演示代替实际接入完成。
- 已有查询安全、取消、终态写保护是接入前置条件，不推迟到 S4。
- 分离前端退订与服务端取消，补齐受影响的事件归属、排序去重和恢复逻辑快速测试；交互验收按下方保留能力清单由用户安排，未执行须记录。
- 完成普通查询、可修正 SQL 错误、验证后回答、预算部分收尾、拒绝、取消和空模型响应的快速 mock 测试。

### S2：完成独立业务定义模块

- 建立定义、版本、候选持久化及接口，S1 fixture 作为一次性 seed 导入，不再运行时并行读取。
- 页面能按数据源 CRUD；冲突与权限有清晰反馈。
- 候选通过真实用户确认进入正式定义，Agent 没有自行确认权限。
- 正式定义与会话临时约定分开；新核心禁用所有旧记忆注入/蒸馏。

### S3：多轮、按需信息和上下文

- 实现状态白名单更新、版本冲突、草稿成功提升与失败不提升。
- 实现来源、数据源、口径、时间、筛选改变后的证据适用性检查。
- Schema 和业务定义目录/详情工具使用相同预算体系；每次模型调用重新选择上下文。
- 输出可检查的 PromptSnapshot / ContextSelectionReport，不建独立管理平台。

### S4：验收与表达

- 完成前端关键发现到证据的展开，图表继续从 Artifact 生成。
- 记录真实模型验证的版本、输入、结果、失败类型和限制；若用户未安排执行，则状态保持“待真实模型验收”。
- walkthrough 只讲可见动作和依据，不编造模型内部推理。
- 有了实际结果后再更新 README、RESUME_HIGHLIGHTS、AI_AGENT_INTERVIEW 中的能力表述；删掉“彻底消灭幻觉”等不可证明的宣传，不把目标提前写成成果。

### S5：切换策略

1. 初期通过服务端临时 `legacy/new` 选择器选择核心，选择结果固定在 generation；不向普通用户增加长期设置。
2. 新核心使用新会话验收，旧会话可继续查看；进入新核心时明确初始化新分析任务，不自动承接旧摘要/记忆状态。
3. 新核心不支持的旧 Artifact 可只读展示，禁止当作满足新口径元数据的证据。
4. 在新核心的必需快速验证通过、用户明确安排的主业务及下方外围保留能力交互验收完成后，才将新核心设为默认并退役旧入口。未完成时明确标为待验收，不无限期维护双核。
5. 切换前回退只影响后续 generation；运行中任务不换核心，不把新状态投喂旧核心。保留兼容性新增表，回退不删新数据。
6. 移除旧 loop、旧 Prompt 压缩路径、隐藏 SQL 修复、异步蒸馏、新界面里的旧记忆入口及仅服务旧设计的配置/测试。仍被外壳复用的文件不按名称一刀切删除。
7. 退役后删除临时选择器，回滚依靠 Git/部署版本，不能保留永久双事实源。数据库历史清理另行决定。

## 3. 轻量业务案例集

现有 `cases.json` 继续是其覆盖题目的数值事实来源；新增 `agent-core-cases.json`（建议路径）描述对话、预期行为与评分依据，可引用现有 case ID，不复制一份易漂移的标准数字。

每例至少包含：id、数据集/种子版本、时间锚点、定义版本、消息序列、关键预期值或参考 SQL、允许的合理路径、必须行为、禁止结论、所需验收类型。不强制字符串或 SQL 文本完全相同。

| 案例 | 预期行为 | 必须拦住的错误 |
| --- | --- | --- |
| C01 口径有歧义 | 已有唯一匹配定义直接用；冲突/缺关键分母时澄清 | 猜激活定义；每次无条件反问 |
| C02 7 日激活对比 | 排除观察期未满用户，确认区间及分母；先验证是否真下降 | 未成熟用户导致虚假下降 |
| C03 渠道拆解与验证 | 对比渠道占比和渠道内表现，验证主要解释；可推翻前提 | 第一个相关现象直接定因果 |
| C04 连续筛选与口径变更 | “只看 Android”检查字段语义；临时换口径更新状态并重查 | 旧总体结果冒充子集；自动覆盖长期口径 |
| C05 定义 CRUD 与确认 | 未确认候选不召回；修改/删除下一轮生效；历史可追溯 | 双源冲突、旧口径继续默认生效 |
| C06 采集缺口/对账差异 | 以 APAC Android 已知缺口或汇总差异为验证题，说明数据限制 | 将缺失直接解释为用户真实流失 |
| C07 SQL 失败与修正 | 结构化错误返回主循环，修改可见，受预算限制 | 工具内部修复、原样无限重试 |
| C08 有限预算 | 仅有部分证据时输出 partial 与待查项，硬取消不再生成 | 假装完成、超时后继续执行 |
| C09 上下文与证据复用 | 小预算下保留当前任务；回读旧结果重画图；新鲜度要求重查 | 孤立工具消息、凭历史文字复述数字 |
| C10 权限与注入 | 外部字段/定义含攻击文本不改变规则，跨源 ID 被拒绝 | 目录缓存/Artifact 绕过授权 |

C05/C07～C10 有大量确定性断言，可用 mock 与 repository 替身快速验证；C01～C04/C06 的分析判断仍需真实模型与人工审查。两类验证各自报告，不互相代替。

## 4. 对照方式与指标

基线采用同一模型、同一数据、同一已确认定义、同一权限与安全工具下的简单问数流程；诊断能力比较时可固定其缺少验证策略，证据复用比较时单独关闭复用。每次只改变一个关注点，避免把缺少口径导致的失败算成新架构的全部收益。

记录：关键值正确性、口径/观察窗口、证据支持程度、是否验证主要解释、不确定性表达、工具次数和预算退出。先逐例判定 pass/fail/needs-review 并保留解释，不急着合成总分。

真实模型采样少时只报告具体案例结果，不声称稳定准确率提升；固定模型与配置降低变化来源，不保证绝对确定性。无 LLM-as-judge、无自动发布门禁、无 dashboard。

### 2026-09-21：S3 多轮状态、条件证据与上下文

**会话状态。** 新增 `AnalysisState`、纯状态校验、`AnalysisStateRepository` 和 `analysis_state` / `analysis_state_draft`。每 generation 创建固定定义版本的草稿；`get_analysis_state` / `update_analysis_state` 提供白名单更新、expectedRevision、显式新任务、临时口径来源绑定、半开时间区间、字段筛选、粒度、时效要求和有证据的假设。每轮首次取数/回读/作图前必须成功确认状态；状态更新不得与查询等工具同批，防止未观察更新结果便继续执行。

成功 finalize 与草稿提升处于同一数据库事务；基于 base_revision 检测并发冲突。失败、取消不提升草稿；缺少草稿或提升冲突时回滚 completed 并以 failed 收尾。补齐 completed 与 cancel_requested 竞争的保护，取消先取得行锁时不提交成功状态。更换数据源强制新任务；同源后续轮次继承成功状态，当前引用定义的更新/删除下一轮刷新并提示，旧假设随条件变化清空。新核心仍不读取旧 MemoryService / SemanticDistiller。

**证据。** 新增 Query Artifact 的 `analysis_context`，记录真实查询时的状态与已选择定义内容快照。新核心回读工具分页，检查归属、成功历史 Turn、数据源权限以及授权表目录/字段策略指纹；目录或策略变化保守拒绝旧结果复用。旧 Artifact 无分析元数据时仍可由旧入口查看，但不能支持新核心推导。条件签名包含 task、数据源、定义版本、临时口径、时间、比较区间、筛选与粒度，不因纯状态 revision 或文字变化强制重复查询。`freshness=current_generation` 拒绝上一轮结果。条件不匹配须重查，或显式 comparison 回读并在最终引用填写 `comparisonLabel`；比较不能绕过跨源、新任务与最新数据要求。图表按当前条件校验，不允许通过图表过滤偷偷改变分析范围。

**按需上下文。** 提供 `list_schema` / `get_schema`、`list_business_definitions` / `read_business_definitions`、`list_analysis_evidence` / `read_query_artifact`，目录及字段有明确 nextOffset。启动不再因超过 20 张表而直接失败，Schema 详情只读取所选表；缓存命中也先授权。正式定义内容在 generation 草稿中固定，模型侧按目录/详情加载，当前引用定义优先。SQL 的模型摘要最多 20 行且有字符上限，完整查询行仍保存在 Artifact，省略情况进入质量约束。

`ContextAssembler` 每次模型调用重新选择规则/当前状态、关键口径、完整工具交互、最多 4 个近期成功新核心 Turn、目录及证据索引。优先保留最近完整工具批次，闭合的旧工具批次可整批移除；不拆开 tool_call/result。必需内容仍超预算则明确失败；供应商明确 context-length 错误只允许一次缩减预算重试并计入模型次数。每次调用的输入估算、选择/省略原因、内容 hash、版本、任务/状态/定义、Schema 详情 hash、Turn/Artifact 引用保存到草稿 context_reports，成功结果也携带报告；不保存私有推理链到报告中。
