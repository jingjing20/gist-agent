# 数据源记忆与分析状态

2026-09-23 起，长期业务语义改为按数据源保存的文本记忆。用户不再选择指标、术语、关系类型，也不填写分子、分母或关联字段表单。共享类型和数据表均使用独立的记忆模型；当前 HTTP 入口是 `/memories` 和 `/memory-candidates`，管理页是 `/memories`。

## 记忆

一条记忆包含标题 `name`、正文 `description`、所属数据源、来源、当前版本及状态。数据源所有者可在管理页新增、修改、删除；修改产生不可变历史版本，删除退出后续检索。读权限遵循数据源授权，写入和确认仅限所有者。

用户发送以 `记住：` 或 `请记住：` 开头的消息时，正文会直接保存到当前数据源。标题取正文第一行的前 80 个字符。保存按来源消息去重，避免同一 generation 重试后重复创建。其他自然语言表述由 Agent 在对话中处理；未经明确指令的提炼结果只可提交为候选，待所有者确认后生效。候选只在成功完成的 generation 后展示，确认和目标版本检查在同一事务中完成。若名称冲突，返回 409，请用户在管理页修改标题。

数据保存在 `datasource_memory`、`datasource_memory_revision` 和 `datasource_memory_candidate`。旧 `business_definition*` 表不参与新设计，开发库重建时删除；不迁移旧定义。

## 分析状态与证据

每轮分析读取当前数据源的记忆快照。Agent 按需查看完整文本，并在分析状态中引用 `(id, version)`。临时约定留在当前任务状态，不自动写入长期记忆。记忆更新或删除后，下一轮移除过期引用并提示重新选择；不会自动升级到新版本。

查询 Artifact 仍记录执行时的记忆版本、时间范围、筛选与粒度。上述条件变化后，旧结果需重新查询或按明确标注的历史条件比较。记忆是业务说明，不是数据事实；SQL、结果和质量信息仍由 Artifact 保存。
