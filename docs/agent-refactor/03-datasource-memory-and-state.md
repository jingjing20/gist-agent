# 数据源记忆与分析状态

2026-09-23 起，长期业务语义改为按数据源保存的文本记忆。用户不再选择指标、术语、关系类型，也不填写分子、分母或关联字段表单。共享类型和数据表均使用独立的记忆模型；当前 HTTP 入口是 `/memories` 和 `/memory-candidates`，管理页是 `/memories`。

## 记忆

一条记忆包含标题 `name`、正文 `description`、所属数据源、来源、当前版本及状态。数据源所有者可在管理页新增、修改、删除；修改产生不可变历史版本，删除退出后续检索。读权限遵循数据源授权，写入和确认仅限所有者。

用户发送以 `记住：` 或 `请记住：` 开头的消息时，只有内容明确、未发现相似已有记忆的单纯口径直接保存到当前数据源。标题取正文第一行的前 80 个字符。保存按来源消息去重，避免同一 generation 重试后重复创建。

2026-10-12 起，应用保守识别混合请求：如“记住：有效订单不包含退款订单。另外帮我看看上个月销售额”，只把第一段口径创建为候选，不保存后续分析请求。涉及更正／修改或已有相似内容时也创建候选；问题、未解析指代和无法可靠分离的命令交给 Agent 提炼或澄清。此识别是语法规则，不承诺理解所有自然语言表达。应用向 Agent 提供实际写入结果，要求不重复提议已保存或已创建的候选。

聊天以持久化的 `memory_notice` 事件展示已保存、待确认、需要提炼或未保存的结果。直接保存的回执包含保存时的完整版本，并提供管理页入口；分析失败或取消不会撤销已经提交的直接保存。候选只在成功完成的 generation 后展示，未确认前不参与长期召回。同一 generation 中相同内容和目标版本的候选去重。

聊天和管理页复用候选编辑器，用户可修改完整内容，再确认新增或显式选择替换已有记忆。确认与目标版本检查在同一事务中完成，目标必须属于候选的数据源；版本变化时返回 409，不覆盖修改。相同确认请求可重试，不会新增重复版本。

聊天中的结果状态、缺失项和候选操作等待生成结束且正文播放完成后显示，避免补充说明抢先出现。候选确认成功后，当前页面展示保存标题、返回版本和后续分析生效范围；不自动重算原分析，也不改写原正文。该确认回执目前属于页面状态，刷新后可在记忆管理页核对正式记忆。Agent 提议文案引导使用下方候选卡片，不展示内部候选标识，也不将单纯候选确认作为分析缺失项。

保存前调用 `POST /memories/related`，根据规范化标题、正文及相邻字符匹配返回最多 5 条同名、同内容或文字相似的有效记忆。页面展示原文和匹配依据，要求核对后再保存；内容或匹配版本变化时重新核对。文字匹配是重复／冲突检查线索，不是业务矛盾判定，不提供向量检索。服务端仍限制同数据源有效记忆名称唯一，名称冲突返回 409。

记忆版本的 `source_message_id` 保留来源 UUID，不作为消息表外键：删除来源对话不能删除长期记忆或其历史，也不能被记忆历史阻止。现有数据库通过 `pnpm migrate:memory-provenance` 做无数据删除的定向升级；完整 schema 应用也移除旧外键。候选表的来源消息外键使用 `ON DELETE CASCADE`，候选随来源消息和生成任务删除，不影响正式记忆；定向升级同时修正已有候选外键。前端仅在删除接口成功后移除对话，失败则保留并报错。

数据保存在 `datasource_memory`、`datasource_memory_revision` 和 `datasource_memory_candidate`。旧 `business_definition*` 表不参与新设计，开发库重建时删除；不迁移旧定义。

## 分析状态与证据

每轮分析读取当前数据源的记忆快照。Agent 按需查看完整文本，并在分析状态中引用 `(id, version)`。临时约定留在当前任务状态，不自动写入长期记忆。记忆更新或删除后，下一轮移除过期引用并提示重新选择；不会自动升级到新版本。

分析结果旁展示“本次采用的业务口径”，仅展示结果快照中与实际 `memoryRefs` 匹配的完整版本；后续管理页修改不影响历史展示。

查询 Artifact 仍记录执行时的记忆版本、时间范围、筛选与粒度。上述条件变化后，旧结果需重新查询或按明确标注的历史条件比较。记忆是业务说明，不是数据事实；SQL、结果和质量信息仍由 Artifact 保存。
