## 目标与阅读顺序

深入学习 Agent 工程是第一目标，可演示、可验证的求职成果是表达方式。项目定位为：**一个能在多轮分析中保持口径、查验证据、发现不足并修正结论的数据分析 Agent**。

准确问数是基础，有限自主诊断是核心。首期围绕 SaaS Growth 数据集，不建设通用 BI 指标引擎或企业级 Agent 平台。

重写范围仅为 Agent 核心；保留 API/Worker、现有外围模块和技术栈。多会话切换期间后台继续生成，切回补齐内容并恢复流式接收，是明确的兼容性要求，见 D19/D20 与 P01～P07 验收清单。

## 使用规则

1. 先读产品决策，再读对应契约，最后按交付阶段实施；不要按旧 Phase 继续加功能。
2. “已确认决策”来自本次讨论，不能在实现中悄悄改变。“实施约定”是为使方案可执行而补充的默认设计，不冒充用户逐项确认的结论；可在首次实现时用具体证据调整并同步更新文档。
3. 接口、类型、工具名描述最终设计目标；是否已经提供，以实施路线中的阶段记录为准。实施时先检查实际依赖，不依赖文档中的理想接口直接拼接旧代码。
4. 每阶段更新交付表，记录实现路径、快速验证结果、未执行的真实模型与交互验收；不新增一套重复的阶段长文。
5. 不把单测通过写成分析正确，不把证据可追溯写成结论已被证明，不把有限案例表现写成通用准确率。
6. 默认只运行快速、非交互式检查。真实外部模型、数据库集成、浏览器 E2E、完整回归和人工交互按用户明确安排执行。
