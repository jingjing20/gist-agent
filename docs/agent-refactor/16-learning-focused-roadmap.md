# 学习主线重构路线图

> 状态：当前执行路线（2026-09-18）
>
> 目标：以可解释、可演示、可比较的方式深入学习 AI Agent 流程、Prompt、上下文工程和记忆系统；生产平台能力作为可选扩展，不再作为核心完成条件。

## 1. 为什么重新收口

Phase 0～5 建立了可靠执行、工具编排、Artifact、上下文和结构化记忆基础。Phase 6 又探索了成本 dashboard、发布门禁、保留清理和 Worker kill E2E。这些能力有生产价值，但继续沿该方向扩张，会让学习重点从“模型如何在受控上下文中做决策”偏移到平台运维。

本路线图不否定已经完成的工程工作。Phase 6 代码保留为 checkpoint 和可选参考，但后续优先级由学习价值决定，不再由生产完备性决定。

## 2. 核心问题

项目接下来集中回答四组问题：

1. **Agent 流程**：模型在什么状态下直接回答、澄清、查询、修正、总结或拒答？代码与 Prompt 各自负责什么？
2. **Prompt**：安全规则、分析原则、工具协议、外部数据和输出规范如何分层，如何知道本次实际使用了哪些模块？
3. **上下文**：历史 Turn、Artifact、Schema 和记忆如何竞争有限 token，为什么某份证据被选择或舍弃？
4. **记忆**：什么内容值得跨轮或长期保存，来源、确认、冲突、纠正和遗忘如何影响后续决策？

## 3. 当前范围

### 核心学习范围

- 单 Agent 的可解释决策循环与显式状态边界。
- Prompt 模块化、版本化、快照和注入边界。
- 完整 Turn、Query/Chart Artifact、Schema 两阶段加载和 token 预算。
- 工作记忆、会话证据与结构化长期记忆的职责边界。
- 支撑上述模块迭代的轻量确定性回归和少量 golden cases。

### 暂不优先

- 生产 Operations Dashboard 与告警平台。
- 供应商价格维护和精细成本核算。
- 多模型生产路由与自动降级矩阵。
- Worker 进程 kill、跨机恢复和完整发布工程。
- 法务保留、不可逆匿名化和企业级数据治理。
- 大规模 LLM-as-judge、重复采样和 CI 发布门禁。
- 多 Agent 框架、向量记忆和复杂 RAG。

这些内容不是错误设计，而是移入 Optional；只有当核心学习问题需要它们时才重新引入。

## 4. 学习阶段

### L1：Agent Loop 与 Prompt 可解释化

目标是让一次回答的每个决策都能被解释，而不是增加更多 Agent。

交付物：

- 将 System Prompt 拆成身份与分析原则、安全边界、Schema/记忆数据区、工具协议、ResultQuality 规则和输出规范。
- 建立 Prompt module registry 和稳定版本，不在字符串拼接中隐式改变策略。
- 建立 `PromptSnapshot`，记录本次启用模块、Schema 表、记忆 ID、历史 Turn 和 token 预算结果；默认不保存敏感原文。
- 把 Agent Loop 的直接回答、澄清、工具执行、结果观察、重规划、完成和拒答出口整理成决策表。
- 保持单 Agent；只有明确失败案例证明职责混乱时，才考虑独立 Interpreter/Planner/Synthesizer 调用。

完成条件：

- 能从一个 generation 还原“模型看到了什么、为什么允许下一步动作”。
- Prompt 结构变化有快照测试，安全规则和外部数据区不能被无意交换顺序。
- 正常查询、澄清、SQL 修正、空结果、注入和拒答路径各有一个确定性案例。

### L2：上下文选择与证据连续性

目标是解释 token 受限时保留了什么以及为什么。

交付物：

- 统一描述 Turn、Artifact、Schema、Memory 四类上下文候选及优先级。
- 输出可检查的 Context Selection Report：候选、选择、压缩级别、估算 token 和舍弃原因。
- 用真实业务问题验证 Schema 两阶段加载，而不是只验证包含目标英文表名的合成案例。
- 建立多轮 Artifact 复用案例，区分交流连续性和证据连续性。

完成条件：

- 给定相同输入快照，选择结果确定且可解释。
- 多轮追问读取 Artifact，不依赖模型复述历史数字。
- 上下文超预算时按完整 Turn 降级，不破坏工具调用链。

### L3：记忆决策与冲突治理

目标是让“记住什么”和“何时使用”成为可观察决策。

交付物：

- 明确工作记忆、Artifact 和长期 MemoryRecord 的边界。
- 为候选提取、用户确认、冲突、纠正、遗忘和过期各建立案例。
- 记录记忆召回原因，以及因本轮要求、Schema 或安全规则被抑制的原因。
- 验证非用户确认的数据推断不会进入长期记忆。

完成条件：

- 任一进入 Prompt 的长期记忆都有来源、状态、版本和召回理由。
- 用户本轮明确要求优先于旧偏好；记忆不能扩大权限或改变系统规则。
- 纠正和遗忘在下一轮立即生效。

### L4：独立评测专题

前三阶段稳定后，再单独设计评测系统。届时先定义被测行为，再选择确定性评分、规则评分或 LLM-as-judge。

预期主题：

- 单轮与多轮数据集建模。
- 正确性、口径、证据一致性、工具效率、安全和拒答质量。
- 固定温度、重复采样、均值与最差表现。
- 评测数据版本、人工审核和基线比较。
- 成本/延迟门槛与质量门槛的权衡。

当前只保留“薄评测”：mock 状态机回归、关键安全测试和少量 golden cases，不建设完整评测平台。

## 5. 下一迭代：L1

下一次编码只推进 L1，顺序固定为：

1. 盘点当前 System Prompt 的规则来源和重复/冲突。
2. 定义 Prompt 模块契约与 `PromptSnapshot`，先写快照测试。
3. 迁移现有 Prompt，保持行为等价。
4. 整理 Agent Loop 决策表，并补齐六类确定性出口案例。
5. 选一个端到端业务问题，形成从输入到记忆的可阅读 walkthrough。

本迭代不修改模型路由、不建设 dashboard、不扩展保留策略，也不引入多 Agent。

## 6. 判断新需求是否进入核心路线

只有同时满足以下条件，需求才进入核心路线：

- 能直接帮助理解 Agent、Prompt、上下文或记忆中的至少一个核心决策；
- 能用具体失败案例说明缺少它会导致什么；
- 有比增加平台复杂度更简单的验证方法；
- 完成后能通过代码、测试或 walkthrough 被观察，而不只是增加配置项。

否则默认进入 Optional 清单。
