# 技术参考导航

用途：快速查询定义并减少手工重复维护。适用读者：开发、Agent、数据库与运维人员。

| 文档/工具 | 来源与用途 |
| --- | --- |
| [API索引](api-index.md) | 按业务领域查每个接口的作用、主要结果、鉴权入口、真实处理器与实现指南 |
| [平台Schema](database-schema.md) | 23张平台表的用途、关键字段解释入口及DDL列定义，不含动态分析源表 |
| [工具与类型](tools-and-contracts.md) | 当前13工具的使用目的、调用条件，以及共享契约的字段含义与消费者 |
| [配置](configuration.md) | 实际环境读取、默认边界与Compose差异，排除敏感值 |
| [用途注释：API](api-descriptions.json) / [表用途](schema-descriptions.json) | 人工根据实现维护中文语义、代码依据与主文档入口，供生成器合并 |
| [generate.py](generate.py) | 提取路由/DDL并合并用途注释；--check只读比较，无服务连接 |

自动参考不是OpenAPI或线上Schema导出。路由与DDL结构来自代码解析；业务用途来自人工阅读真实实现后的注释，两种依据明确区分。业务关系主要维护在[design](../design/README.md)，运行机制在[guides](../guides/README.md)。


需要理解关键字段为什么存在、由谁读写时，请读[数据模型设计](../design/data-model.md)；需要推演一次执行的写入/提交/回滚时，请读[数据库持久化指南](../guides/database-persistence.md)。表参考逐表链接到对应设计章节，完整字段解释只有一个维护位置。

## 变更时怎样维护

1. 新增、删除或改名接口/表时，同步对应用途JSON条目；依据填写真实路径与符号，讲解入口指向主要指南或设计章节。新增入口缺少说明、删除后遗留说明会被生成器拒绝。
2. 已有接口/表内部行为变化时，人工复核作用、返回意义、权限与状态限制；源码符号存在并不能证明说明仍正确。
3. 运行`python3 docs/reference/generate.py`更新生成页，再运行`python3 docs/verify.py`检查一致性、链接、标题锚点和文档结构。不要直接编辑生成页，因为重生成会覆盖它。

生成器采用当前源码格式的轻量解析，并核对用途覆盖集合及证据路径/符号；装饰器或DDL格式变化时同步维护解析器。用途说明不复制完整协议或指南，避免把同一业务流程分散成多份。
