# Gist Agent 面试参考

以当前实现为依据，重点解释选择、失败和验证，不背诵已退役架构。实现状态及验证限制见[交付页](../agent-refactor/05-delivery-and-validation.md)。

## 1. 为什么称为 Agent？

模型可以选择工具、接收真实执行反馈、修改下一步，并提交结构化业务结果。这个多步决策循环由 [AnalysisAgent](../../apps/worker/src/analysis/analysis-agent.ts)实现，不是单次生成 SQL 后直接展示。

自主性有边界：模型选择调查路径，代码限制身份、权限、参数、证据、预算及终态。它不是固定“先渠道后平台”的业务工作流，也不是开放式无限调查。

## 2. 为什么自己维护循环？

项目需要把工具协议、失败反馈、预算、证据校验和 generation 外壳结合起来。手写循环让这些约束可直接检查；代价是需要自行处理流式工具参数拼接、tool_call 配对、取消和异常。

不把“未使用框架”本身当作优势。应能说明某个具体约束如何实现、用什么失败案例验证，以及维护成本是什么。

## 3. Tool 与 Agent 如何区分？SQL 执行器是什么？

Tool 接受一次调用并返回观察；Agent 根据目标和观察选择后续行动。AST 检查、权限校验、超时等确定性逻辑不构成模型决策闭环。

当前 SQL 类虽仍名为 SqlExecutorAgent，但其[实现](../../apps/worker/src/chat/agents/sql-executor.ts)不调用模型。工具执行失败后由主 Agent 修正，再经过相同安全检查。不能继续讲旧版本“子 Agent 静默修语法”的故事。

## 4. 如何限制危险 SQL？

只允许单条 PostgreSQL SELECT，检查 AST、表字段权限和危险表达式；限制结果行数，使用只读查询连接、事务与 statement_timeout，并传递取消。

LIMIT 不限制扫描成本，AST 不证明业务语义正确。解析失败可能是合法语法不受支持，必须返回反馈改写，不能绕过检查。独立账号需要实际部署配置，不能仅因源码支持就声称已经启用。

## 5. 业务定义与记忆有什么区别？

当前长期知识收口为数据源级、用户确认的业务定义；查询结果存在 Artifact，任务条件存在 AnalysisState。三者职责不同。

Agent 只能提出候选，不能自行确认正式定义。正式修改保留版本，下一轮刷新；临时口径绑定用户消息，只影响当前任务。没有后台模型从对话自动蒸馏出另一套事实源。

## 6. 如何支持连续追问？

每轮显式确认或修改状态，查询保存当时的定义、时间、筛选和粒度。条件变化后检查旧证据适用性，无法复用时重查；纯重画图可以回读匹配结果。

“只看 Android”不仅是加一个过滤条件，还要确认平台字段代表什么。状态中记录了条件，不等于 SQL 一定正确实现了条件，这仍要通过实际查询和案例审核。

## 7. 如何处理上下文预算？

[ContextAssembler](../../apps/worker/src/analysis/context-assembler.ts)按确定性优先级选择当前任务、必要状态和定义、完整工具交互、近期轮次及目录。工具调用与结果成组保留或丢弃，不能留下孤立 tool 消息。

输出选择报告说明输入选择和省略，不等于还原模型内部思维。Token 是估算，必要信息仍放不下时应明确失败，不静默截断当前要求。

## 8. 证据引用能保证答案正确吗？

不能。代码可以检查引用是否存在、可访问、已观察、条件适用和质量受限；不能一般性证明解释充分或因果成立。

图表来自 Artifact 字段映射，降低手抄数值风险；主要解释要求验证查询，但“多查了一次”也不自动等于完成有效验证。真实语义通过 C01～C10 对照审核。

## 9. 如何防止失败状态污染下一轮？

运行中修改先保存为 generation 草稿。成功 finalize 时在事务中提升为会话状态；失败、取消或版本冲突不提升草稿。候选也只在成功任务后进入可确认流程。

需区分模型的业务出口和任务执行状态。partial 可以是合法业务提交；取消和协议失败不能装成 completed。

## 10. SSE 断开后为什么不取消任务？

API 接收与订阅、Worker 执行分离。切换会话或断网只是失去订阅，不代表用户要取消。切回后通过快照与事件游标补齐，前端按 conversationId / generationId 去重并归属。

真正取消通过明确请求和服务端终止条件传播。重点验收切换、迟到事件、重复订阅、重连与取消竞争，见 P01～P07；不能只展示 SSE 正常输出就声称这些行为通过。

## 11. 目前能证明什么，不能证明什么？

历史 mock、类型检查和构建验证了部分代码路径和结构约束；有本机数据库重建与结构核验记录。真实模型业务语义、完整数据库并发和交互仍需验收。

面试可展示一个可重放的失败及修复，例如 PostgreSQL AST 方言检查一致性、提交字段混用反馈或解析失败返回主循环。明确复放使用模拟数据库还是实际模型，不把二者混为一谈。
