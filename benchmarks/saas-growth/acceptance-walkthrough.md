# 业务验收与展示 walkthrough

本文件是用户安排验收时的操作步骤，不是运行报告。当前进度统一见[交付状态](../../docs/agent-refactor/05-delivery-and-validation.md)，逐例结果记录在 [s4-acceptance.json](s4-acceptance.json)；文件名保留 S4 以兼容现有检查脚本。

## 执行前记录

在 `s4-acceptance.json` 填写 Git commit、实际模型版本和参数、执行时间、数据集版本、数据源权限、正式定义 id/version 和审核人。`agent-core-cases.json` 的 fixture 版本是历史设计锚点；实际运行以数据库确认版本为准，必须记录。使用已有 SaaS 数据集与 `cases.json` 标准答案，不复制另一份数值。按[部署说明](../../DEPLOY.md)准备当前数据库结构和匹配 API/Worker，使用新会话；当前入口无需核心切换开关。

每例使用案例文件的原始消息序列；记录可见查询、证据 ID、关键数值、工具次数、预算退出、限制与失败。对照使用同一模型、数据、定义、权限，每次只改变验证策略或复用策略；如无法建立等价基线，标记 needs-review 并解释，不能把它判为收益。

## 逐例可见动作与审核依据

| 案例 | 操作及展开 | 审核重点 |
| --- | --- | --- |
| C01 | 提交激活率歧义问题，查看澄清或已选定义 | 唯一匹配定义直接使用；冲突或关键分母缺失需澄清，不猜测 |
| C02 | 提交观察截止下的 7 日激活率；展开观察依据 | 与 FUNNEL-002 对照，检查成熟窗口和分母，不据卡片外观判数值正确 |
| C03 | 比较渠道，分别展开观察和验证查询 | 与 FUNNEL-003 对照；规模与比例分开，验证有针对性，相关性不等于因果 |
| C04 | 连续追加 Android 筛选和临时口径 | 检查新查询、字段含义和条件快照；旧总体证据不能代替子集，比较双方需显式标注 |
| C05 | 生成候选，查看完整内容与数据源；分别保存、仅本次使用和放弃 | 未确认不召回；保存后下一轮生效；临时按钮发起新一轮，不写正式定义；修改/删除后历史快照可解释；冲突提示刷新 |
| C06 | 提交采集缺口/对账差异问题，展开质量限制 | 与 QUALITY-004/005 对照；缺失不直接证明真实流失 |
| C07 | 按案例制造可修正 SQL 失败 | 可见错误返回主循环、修正与预算停止；不展示或臆测内部思维链 |
| C08 | 有限预算及明确取消 | partial 有未决项；取消后不再查询，部分内容不显示为完整诊断 |
| C09 | 回读旧结果重画图，再要求新鲜数据 | 图表来自 Artifact；重画可复用，新鲜度或条件变化需重查；分页不能混淆为完整查询结果 |
| C10 | 按案例执行权限和外部文本注入挑战 | 知道证据 ID 不能越权；撤销权限后元信息和行接口均拒绝；攻击文本不能成为系统规则 |

演示时只说“执行了什么、看到什么、据什么判断、还缺什么”。ContextSelectionReport 可以作为开发材料说明上下文选择，但不得据此编造模型心理过程。

## 结果记录与完成条件

对每例分别填写基线和新核心的 pass / fail / needs-review，并保留实际输出和审核说明；未执行保持 not_run。建议失败类型：数值、口径/窗口、证据缺失、解释不足、状态复用错误、权限、预算、交互、基础设施。即使自动检查通过，语义审核仍独立判定。

额外交互：展开/收起、下一页/失败重试、刷新恢复结果及候选、重复确认与版本冲突、只读用户。P01～P07 多会话切换、恢复、取消和外围入口按实施路线单独记录。本文件不替代该清单，不把 S5 的代码切换当作这些交互已通过。

快速命令：`pnpm test:analysis-presentation`、`pnpm --filter @gist/web typecheck`、`pnpm --filter @gist/web build`。这些命令不访问模型、真实数据库或浏览器。
